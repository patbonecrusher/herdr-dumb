The agent multiplexer your security team can approve.

herdr-dumb runs your coding agents in persistent, detachable terminals and tells you which ones need attention, without opening network connections, updating itself, or running third-party code. It is built for locked-down environments such as GCC High.

What we took out, and why

Upstream herdr is a great tool for a laptop. In a regulated environment, every feature that reaches the network, changes the installed software, or runs code from outside the reviewed source is a separate approval. We removed those features instead of asking reviewers to vet them.

SSH machines and remote bridges

Connected to saved SSH hosts, ran a bridge there, and showed remote panes in the local window.

Risk: outbound connections and one machine driving terminals on another. A remote-control and data-exfiltration channel.

Self-update and release channels

Downloaded and installed new binaries from GitHub releases.

Risk: software that replaces itself. Installed software should change only through a reviewed release.

Detection-rule downloads

Fetched updated agent-detection manifests from the internet at runtime.

Risk: behavior that changes after installation. herdr-dumb only uses the rules compiled into the binary.

Plugins and the marketplace

Installed and ran third-party plugin code, plugin panes, and plugin keybinding actions.

Risk: unsandboxed code from outside the reviewed source. The runtime, loader, and registry are deleted; legacy plugin requests are rejected.

Clipboard image forwarding

Wrote images pasted from the client to a temp directory and typed the path into the pane.

Risk: outside data written to disk and handed to whatever runs in the pane. The message is now ignored.

What you keep

Everything that makes herdr useful for agents running on the machine in front of you.

Persistent sessions

Close the client and your agents keep working. Reattach any time; layouts restore after a restart.

Agent status at a glance

Every pane is marked working, blocked, or idle, so you never hunt for the agent waiting on you.

Your existing agents

Claude Code, Codex, Cursor, OpenCode and more, unwrapped. herdr-dumb owns the terminals, not the agents.

Local CLI and API

Agents can spawn panes, read output, and wait on each other over a local socket.

Keyboard and mouse

tmux-style prefix keys and click, drag, and split, in the terminal you already use.

Isolated install

Separate herdr-dumb config and state. It never reads or changes an upstream herdr install.

Don't trust us. Check.

Every claim on this page can be verified from the public source in a few minutes. These are the checks we suggest to reviewers.

1

No networking libraries

List the resolved dependency tree and look for HTTP, TLS, or SSH crates. There are none.

cargo tree -e normal --prefix none | grep -iE 'http|reqwest|ureq|hyper|tls|ssl|ssh|curl'
2

No sockets on the network

The source opens no TCP or UDP sockets. Client and server talk over a Unix-domain socket on the local machine.

grep -rnE 'TcpStream|TcpListener|UdpSocket' src
3

No code loading

Plugin commands are gone from the CLI, and plugin API calls return feature_disabled.

$ herdr-dumb plugin list
unknown command: plugin (plugin support has been removed)
4

Reproducible, public builds

Release binaries are built by GitHub Actions from tagged commits on master. Windows packaging verifies Microsoft's package and Authenticode signatures, pinned hashes, and static CRT linkage. You can also build from source with just build.

What herdr-dumb does not do

Approval decisions need the limits too.

  • It does not make your agents offline. Coding agents run in herdr-dumb panes and still call their own model APIs. Govern them with your agent and network policy.
  • It does not sandbox panes. Programs in panes run as you, with your permissions, exactly as in any terminal.
  • It is not certified. Removing features reduces the attack surface; whether it meets your authorization requirements is your organization's decision.
  • It does not update itself. Moving to a new version is a manual, reviewable step.
